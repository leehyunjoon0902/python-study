# 코드 공부 순서 (발표 준비용)

`food_chain` 폴더에는 파일이 10개, 약 5,250줄 있습니다. 발표를 위해 꼼꼼히 읽을 것은 **세 파일의 일부, 합쳐서 약 700줄**입니다. 나머지는 화면·그림·측정 도구라 무엇을 하는지만 알면 됩니다.

이 문서는 어떤 파일을 어떤 순서로, 어디까지 읽으면 되는지를 정리한 것입니다. 모델의 설명과 결과는 [발표_준비_노트.md](발표_준비_노트.md), 실행 방법은 [실행_방법.md](실행_방법.md)에 있습니다.

## 1. 무엇을 얼마나 볼지

| 파일 | 줄 수 | 역할 | 볼 정도 |
|---|---|---|---|
| `config.py` | 276 | 모든 수치와 규칙의 스위치 | **전부 읽기** |
| `rl.py` | 286 | Q-Table, SARSA·Q-Learning, 규칙 기반 정책 | **전부 읽기** (핵심) |
| `world.py` | 1,083 | 환경: 지형, 관측, 한 step의 처리, 보상 | **함수 4개만** |
| `train.py` | 129 | 학습 반복문, ε·α 일정, 교대 학습 | 훑어보기 |
| `simulation.py` | 351 | 평가 실행과 결과 저장 | 앞부분만 |
| `analysis.py` | 378 | 로트카-볼테라(LV) 유사성 측정 | 개념만 |
| `__main__.py` | 84 | 명령어를 받아 위 파일들을 호출 | 구조만 |
| `viewer.py`, `plots.py` | 2,650 | 시뮬레이션 화면과 차트 | 읽지 않아도 됨 |

전체 흐름은 한 줄로 이렇습니다.

```
config(수치) → world(환경: 관측 · 행동 처리 · 보상) ⇄ rl(행동 선택 · Q 갱신) → train(반복 학습) → simulation(평가) → analysis · plots(측정 · 그림)
```

## 2. 읽는 순서

### 1단계. 뷰어를 먼저 돌려 본다 (10분)

코드를 읽기 전에 `run_viewer.py`를 실행해 화면을 봅니다. 동물을 클릭해 시야와 energy, hydration을 확인하세요. 코드의 변수가 화면의 무엇인지 연결해 두면 이후가 빨라집니다.

### 2단계. `config.py` (20분)

주석이 자세해서 설계 설명서처럼 읽힙니다. 이 파일만 읽어도 "어떤 세계인가"를 말할 수 있습니다.

| 볼 것 | 뜻 |
|---|---|
| `SPECIES`, `HERBIVORES`, `CARNIVORES` | 4종과 초식·육식 구분 |
| `PREY`, `DIET` | 누가 누구를 먹는가. 토끼는 풀, 사슴은 관목 |
| `VISION`, `NEAR_DIST` | 종별 시야와 "가까움"의 경계 |
| `PARAMS[종]` | 이동 비용, 갈증, 수명, 번식 조건, 사냥 조건 |
| `HUNT[(포식, 피식)]` | 포획 확률, 얻는 energy, 보상 |
| `BURROW_FRACTION`, `BROWSE_*` | 토끼 굴과 관목의 비율 |
| `ALPHA`, `GAMMA`, `EPSILON_*`, `TRAIN_*` | 학습률, 할인율, 탐험 비율, 학습 길이 |
| `ALGORITHM` | 종별 알고리즘(초식 SARSA, 육식 Q-Learning) |

주석에 "70 → 40"처럼 화살표가 있는 값은 조정 과정에서 바뀐 값이고, 옆에 바꾼 이유가 적혀 있습니다. "왜 이 값인가"라는 질문의 답이 여기 있습니다.

### 3단계. `rl.py` (40분, 가장 중요)

강화학습 수업 내용이 그대로 들어 있는 파일입니다. 발표 질문의 대부분이 여기서 나옵니다. 위에서 아래로 순서대로 읽으면 됩니다.

**① State의 구성 (`HERBIVORE_SHAPE`, `CARNIVORE_SHAPE`)**

State는 몇 개의 작은 숫자를 묶은 것입니다.

| 종 | 성분 | State 수 |
|---|---|---|
| 토끼 | energy 3 × hydration 3 × 먹이 방향 5 × 물 방향 5 × 위험 방향 5 × 위험 거리 3 | 3,375 |
| 사슴 | 위와 같음 × 달리는 방향 5 | 16,875 |
| 여우 | energy 3 × hydration 3 × 먹이 방향 5 × 먹이 거리 3 × 물 방향 5 | 675 |
| 늑대 | 위와 같음 × 먹이 크기 3 | 2,025 |

행동은 5개입니다(정지, 위, 아래, 왼쪽, 오른쪽). Q-Table은 "State 수 × 5" 크기의 표입니다.

**② 인코딩 (`encode_herbivore` 등)**

여러 성분을 하나의 번호로 합치는 함수입니다. 진법 변환과 같은 원리입니다.

```python
def encode_herbivore(o):
    return ((((o[0] * 3 + o[1]) * 5 + o[2]) * 5 + o[3]) * 5 + o[4]) * 3 + o[5]
```

**③ 행동 선택 (`QTable.select`, `greedy`)**

ε-greedy입니다. ε의 확률로 무작위 행동을, 그 밖에는 Q값이 가장 큰 행동을 고릅니다.

```python
def select(self, state, epsilon, rng):
    if epsilon > 0.0 and rng.random() < epsilon:
        return rng.randrange(N_ACTIONS)
    return self.greedy(state, rng)
```

**④ 두 알고리즘의 차이 (`update_sarsa`, `update_qlearning`)**

두 함수를 나란히 놓으면 다른 곳은 한 군데뿐입니다.

```python
def update_sarsa(self, s, a, r, s2, a2, alpha, gamma):
    row = self.q[s]
    row[a] += alpha * (r + gamma * self.q[s2][a2] - row[a])      # 실제로 고른 다음 행동 a2의 값

def update_qlearning(self, s, a, r, s2, alpha, gamma):
    row = self.q[s]
    row[a] += alpha * (r + gamma * max(self.q[s2]) - row[a])     # 다음 상태에서 가장 큰 값
```

- **SARSA (초식):** 다음에 실제로 할 행동의 값을 씁니다. 탐험하다 실수하는 것까지 반영하므로 조심스러운 행동을 배웁니다.
- **Q-Learning (육식):** 다음 상태에서 가능한 최선의 값을 씁니다. 탐험과 무관하게 최선의 행동을 기준으로 배웁니다.

**⑤ 한 step 안에서의 순서 (`QPolicy.act`)**

이 프로젝트는 "지연 갱신"을 씁니다. 동물이 다음 자기 차례에 새 State를 보고 행동을 고른 순간, 직전 행동에 대한 갱신을 합니다. 그 사이에 받은 보상은 `reward_acc`에 쌓아 둡니다.

```python
def act(self, world, a, obs):
    s = self.encode(obs)                                  # 지금 State
    action = self.table.select(s, self.epsilon, self.rng) # 지금 할 행동
    if self.learn:
        if a.prev_state >= 0:                             # 직전 전이를 이제 갱신
            ...update_sarsa(...) 또는 update_qlearning(...)
        a.prev_state = s
        a.prev_action = action
        a.reward_acc = 0.0
    return action
```

동물이 죽으면 `died`가 불려 마지막 갱신(`update_terminal`)을 합니다. 죽음에는 다음 State가 없으므로 보상만으로 갱신합니다.

**⑥ 규칙 기반 정책 (`RulePolicy.act`, `_flee`)**

사람이 직접 쓴 규칙입니다. 학습된 정책과 비교하는 기준이고, 뷰어에서 `--policy rule`로 볼 수 있습니다. "포식자가 보이면 도망, 목마르면 물가로, 아니면 먹이 쪽으로"의 우선순위가 어떻게 쓰여 있는지 확인하세요.

**⑦ Q 공유**

파일 맨 위 설명에 있듯이 종별 Q-Table 1개를 그 종의 모든 개체가 함께 씁니다. 토끼 120마리가 표 하나를 같이 채우므로 학습이 빠릅니다.

### 4단계. `world.py`에서 함수 4개만 (40분)

1,083줄을 다 읽을 필요는 없습니다. 아래 네 함수만 봅니다.

**① `observe(a)` — 동물이 무엇을 보는가**

함수 맨 위의 설명(docstring)이 State 각 성분의 뜻을 정리해 둡니다. 이 설명만 읽어도 충분합니다. 핵심은 세 가지입니다.

- energy와 hydration은 35, 70을 경계로 3단계로 나눕니다.
- 방향은 0(없음)과 1~4(네 방향), 거리는 0(없음), 1(가까움), 2(멂)입니다.
- 동물은 자기 시야 안만 봅니다(부분 관측). 굴 안의 토끼는 포식자에게 보이지 않습니다.

**② `step(controllers)` — 한 step의 전체 순서**

20줄 남짓의 짧은 함수입니다. 살아 있는 모든 개체가 무작위 순서로 한 번씩 "관측 → 행동 선택 → 적용"을 합니다.

```python
for a in order:
    if a.alive:
        ctrl = controllers[a.species]
        apply(a, ctrl.act(self, a, observe(a)), controllers)
```

`controllers`는 종별 정책(학습된 정책, 규칙 기반, 무작위 중 하나)입니다. 환경은 정책이 무엇인지 모르고 행동 번호만 받습니다.

**③ `_apply(a, action, controllers)` — 행동의 결과와 보상**

가장 긴 함수(약 260줄)입니다. 전부 읽지 말고 주석의 번호(`# 1) 이동` 등)를 따라가며 **`reward +=`가 나오는 줄만** 찾아보세요. 보상이 언제 얼마나 주어지는지가 여기에 다 있습니다.

| 순서 | 하는 일 |
|---|---|
| 이동 | 막히면 작은 벌점. 먹이 칸으로 들어가면 덮치기 시도. 사슴은 조건이 맞으면 질주 |
| 사냥 | 배고픈 포식자가 사냥 반경 안의 먹이를 확률적으로 포획 |
| 먹기 · 마시기 | 초식은 풀이나 관목, 물가에서는 물. 부족한 만큼 보상이 커짐 |
| 대사 | energy와 hydration 감소 |
| 번식 | 조건이 맞으면 `_breed` 호출 |
| 사망 | 아사, 탈수, 노화. 죽으면 큰 벌점 |

**④ `_breed(a, p)` — 번식**

번식할 때 부모가 `breed_cost`만큼의 energy를 내고 새끼가 그 energy로 시작합니다. 먹이를 많이 먹어야 연속으로 번식할 수 있어서, 포식자 수가 먹이량을 따라가게 됩니다. 늑대는 여기에 영역성(`territory_limit`)이 더해집니다.

### 5단계. `train.py` (15분)

`plan`과 `train` 두 함수입니다.

- **`_epsilon`, `_alpha`:** 탐험 비율 ε과 학습률 α가 학습이 진행될수록 줄어듭니다.
- **`plan` (교대 학습):** 전체의 40%는 초식만 학습(이때 육식은 규칙 기반), 다음 40%는 육식만 학습, 나머지 20%는 10 episode씩 번갈아 학습합니다. 한쪽을 고정해 두면 상대가 계속 바뀌는 문제(비정상성)가 줄어듭니다.
- **`train`:** episode마다 `World(mode="train")`을 새로 만들어 `world.step`을 반복합니다. 학습 모드에서는 번식이 꺼지고, 죽은 개체는 바로 다시 생깁니다. 개체수가 유지되어야 고르게 학습되기 때문입니다.

### 6단계. 나머지는 개념만

- **`simulation.py`:** `Simulation` 클래스(뷰어가 쓰는 한 판의 시뮬레이션)와 `evaluate`(세 정책을 같은 seed로 돌려 비교)만 알면 됩니다. 평가 모드에서는 학습이 꺼지고 번식과 사망이 켜집니다.
- **`analysis.py`:** `analyze_pair`가 중심입니다. 개체수를 이동 평균으로 매끄럽게 한 뒤, 자기상관으로 주기를, 교차상관으로 포식자 지연을 구합니다.
- **`__main__.py`:** 명령어 옵션을 읽어 위 함수들을 부릅니다.

## 3. 한 step 따라가 보기 (토끼 한 마리)

전체 구조를 잡는 가장 좋은 방법은 한 동물의 한 step을 손으로 따라가는 것입니다. 아래는 예시 값입니다.

**상황:** 토끼의 energy 50, hydration 80. 왼쪽에 풀이 있고, 이미 물가에 있으며, 시야 안에 포식자가 없습니다.

1. **관측 (`world.observe`)**
   - energy 50 → 1단계(35 이상 70 미만), hydration 80 → 2단계(70 이상)
   - 먹이 방향 3(왼쪽), 물 방향 0(이미 물가), 위험 방향 0(없음), 위험 거리 0(없음)
   - 관측 = `(1, 2, 3, 0, 0, 0)`
2. **인코딩 (`encode_herbivore`)**
   - `((((1×3 + 2)×5 + 3)×5 + 0)×5 + 0)×3 + 0 = 2100`
   - 이 토끼의 State 번호는 2100입니다.
3. **행동 선택 (`QTable.select`)**
   - Q-Table의 2100번 줄에 있는 값 5개 중 가장 큰 것을 고릅니다. 학습 중이면 ε의 확률로 무작위 행동을 합니다.
4. **직전 전이 갱신 (`QPolicy.act` 안의 `update_sarsa`)**
   - 직전 step의 (State, 행동)과 그 사이에 쌓인 보상, 지금의 State 2100과 방금 고른 행동으로 Q값을 고칩니다.
5. **행동 적용 (`world._apply`)**
   - 왼쪽으로 이동 → 풀을 먹어 energy 증가 → 배고팠던 만큼 보상 → 이동 비용만큼 energy 감소, 갈증만큼 hydration 감소 → 번식 조건 확인 → 사망 조건 확인
   - 이때 받은 보상은 `reward_acc`에 쌓였다가 다음 차례의 4번에서 쓰입니다.

같은 과정을 여우로 해 보면 2번에서 `encode_carnivore`를, 4번에서 `update_qlearning`을 쓰는 점만 다릅니다.

## 4. 공부하는 방법

- **발표 노트와 나란히 읽기.** 발표 노트의 3절(설계)이 코드와 같은 순서로 설명하고, 11절에 코드 지도가 있습니다. 노트에서 개념을 읽고 코드에서 해당 함수를 찾아 확인하는 방식이 가장 빠릅니다.
- **수치를 하나 바꿔 돌려 보기.** 예를 들어 `config.py`에서 여우의 포획 확률(`HUNT[("fox", "rabbit")]`의 `catch`)을 올리고 규칙 기반 뷰어를 돌리면 토끼가 빨리 사라집니다. 직접 본 것으로 "왜 이 값인가"에 답할 수 있습니다. 실험이 끝나면 값을 되돌리세요.
- **테스트를 예제로 쓰기.** `tests/test_food_chain_core.py`에는 "굴 안의 토끼는 잡히지 않는다" 같은 규칙이 짧은 코드로 들어 있습니다. 규칙이 헷갈릴 때 관련 단어로 검색해 보세요.
- **함수 이름으로 찾기.** 이 문서는 줄 번호 대신 함수 이름을 적었습니다. VS Code에서 `Ctrl+Shift+O`로 파일 안의 함수 목록을 열어 이동하면 됩니다.

## 5. 발표에서 답할 수 있어야 하는 것

코드를 읽으며 아래 질문의 답을 자기 말로 만들어 두면 충분합니다.

| 질문 | 볼 곳 |
|---|---|
| State는 무엇으로 이루어지고 왜 그렇게 나눴는가 | `rl.py`의 `*_SHAPE`, `world.observe`의 설명 |
| 보상은 언제 얼마나 주어지는가 | `world._apply`의 `reward +=`, `config.HUNT`, `config.REWARD_*` |
| SARSA와 Q-Learning은 코드에서 어디가 다른가 | `rl.py`의 `update_sarsa`, `update_qlearning` |
| 왜 초식은 SARSA, 육식은 Q-Learning인가 | 발표 노트 2절과 예상 질문 |
| ε-greedy는 어떻게 구현했고 ε은 어떻게 변하는가 | `QTable.select`, `train._epsilon` |
| 학습 때와 평가 때 환경은 어떻게 다른가 | `train.train`, `World`의 `mode` |
| 교대 학습은 왜 하고 어떻게 하는가 | `train.plan` |
| 규칙 기반 정책과 학습된 정책은 무엇이 다른가 | `RulePolicy`, `QPolicy` |
| 한 종의 개체들이 표 하나를 공유하는 이유는 | `rl.py` 맨 위 설명 |
| 포식자 수가 먹이량을 따라가게 만든 장치는 | `world._breed`, `config.ENERGY_BUDGET_BREEDING` |
