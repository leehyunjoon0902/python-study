# 실행 방법 (먹이사슬 생태계 강화학습)

이 문서는 프로젝트를 받아서 실행하는 방법을 정리한 것입니다. 모델 설명과 결과는 [발표_준비_노트.md](발표_준비_노트.md)에 있습니다.

## 1. 한눈에 보기

가장 자주 쓰는 것은 시뮬레이션 화면(뷰어)을 띄우는 일입니다. 학습된 결과가 함께 들어 있으므로 학습 없이 바로 실행할 수 있습니다.

- **버튼으로 실행:** VS Code에서 `run_viewer.py`를 열고 오른쪽 위 ▶ 버튼을 누릅니다.
- **명령어로 실행:** 프로젝트 폴더에서 `python -m food_chain --watch --policy rule`을 실행합니다.

| 하고 싶은 일 | 명령 | 걸리는 시간 |
|---|---|---|
| 시뮬레이션 화면 보기 (규칙 기반) | `python -m food_chain --watch --policy rule` | 즉시 |
| 시뮬레이션 화면 보기 (학습된 정책) | `python -m food_chain --watch` | 즉시 |
| 다시 학습 | `python -m food_chain --train` | 약 6분 |
| 정책 비교 평가 | `python -m food_chain --eval` | 수 분 |
| 포식자 없음 대조까지 평가 | `python -m food_chain --eval --eval-ablation` | 수 분 |
| 로트카-볼테라(LV) 유사성 측정 | `python -m food_chain --lv --policy rule` | 수 분 |
| 차트 다시 그리기 | `uv run python -m food_chain --plots` | 약 30초 |
| 테스트 | `python -m unittest tests.test_food_chain_core tests.test_food_chain_analysis` | 약 20초 |

모든 명령은 **프로젝트 폴더(이 저장소의 최상위 폴더)** 에서 실행합니다. 다른 폴더에서 실행하면 `food_chain`을 찾지 못합니다.

## 2. 처음 받았을 때

### 2-1. 받기

처음 받는 경우입니다.

```powershell
git clone https://github.com/leehyunjoon0902/python-study.git
```

이미 받아 둔 경우에는 프로젝트 폴더에서 최신 내용만 가져옵니다.

```powershell
git pull
```

### 2-2. 필요한 것

- **Python 3.12 이상.** 시뮬레이션, 뷰어, 학습, 평가, LV 측정은 Python에 기본으로 들어 있는 기능만 씁니다. 따로 설치할 패키지가 없습니다.
- **uv (차트를 다시 그릴 때만).** 차트는 matplotlib으로 그리는데, 이 패키지는 프로젝트 환경(`.venv`)에 들어 있습니다. `uv run`으로 실행하면 처음 한 번 자동으로 설치됩니다.

## 3. 버튼으로 실행하기 (VS Code)

VS Code에 Microsoft의 **Python 확장**이 설치되어 있어야 합니다. 그리고 파일 하나가 아니라 **"폴더 열기"로 프로젝트 폴더를 열어야** 합니다.

### 3-1. 뷰어만 띄우기

1. `run_viewer.py`를 엽니다.
2. 오른쪽 위의 ▶ 버튼을 누릅니다.

정책이나 지도를 바꾸려면 파일 안의 두 값을 고칩니다.

```python
POLICY = "rule"   # 'rule' = 규칙 기반, 'trained' = 학습된 정책, 'random' = 무작위
SEED = 42         # 초기 배치 번호. 바꾸면 다른 지도에서 시작한다
```

`food_chain` 폴더 안의 파일을 직접 ▶로 실행하면 오류가 납니다. 그 파일들은 서로를 불러 쓰는 패키지의 일부라 단독으로는 실행되지 않습니다. 그래서 바깥에 `run_viewer.py`를 따로 두었습니다.

### 3-2. 학습·평가도 버튼으로 실행하기

1. 왼쪽 사이드바의 "실행 및 디버그"를 누르거나 `Ctrl+Shift+D`를 누릅니다.
2. 위쪽 목록에서 항목을 고릅니다.
3. 초록색 ▶를 누르거나 `F5`를 누릅니다.

| 목록의 항목 | 하는 일 |
|---|---|
| 뷰어 (규칙 기반) | 시뮬레이션 화면. 개체수가 크게 출렁입니다 |
| 뷰어 (학습된 정책) | 시뮬레이션 화면. 강화학습으로 배운 행동입니다 |
| 학습 (--train) | 4종을 다시 학습합니다 |
| 평가 (--eval) | 무작위 / 규칙 기반 / 학습된 정책을 비교합니다 |
| LV 측정 (--lv, 규칙 기반) | 진동의 주기와 포식자 지연을 잽니다 |
| 차트 다시 그리기 (--plots) | PNG 차트를 새로 만듭니다 |

"차트 다시 그리기"만 matplotlib이 필요합니다. 프로젝트 폴더에서 `uv sync`를 한 번 실행해 `.venv`를 만든 뒤, VS Code 오른쪽 아래에서 Python 인터프리터를 `.venv`로 고르세요.

## 4. 명령어 자세히

### 4-1. 뷰어 `--watch`

시뮬레이션이 돌아가는 모습을 창으로 봅니다.

```powershell
python -m food_chain --watch --policy rule
```

- `--policy`는 동물이 행동을 무엇으로 정할지 고릅니다. 환경(지형, 수치, 번식·사망 규칙)은 세 경우 모두 같습니다.

| 값 | 뜻 | 언제 쓰나 |
|---|---|---|
| `rule` | 사람이 직접 써 넣은 규칙("포식자가 보이면 도망, 목마르면 물가로" 등) | 포식자–피식자 진동을 크게 보여 줄 때 |
| `trained` (기본) | 강화학습으로 채운 Q-Table에서 가장 값이 높은 행동 | 프로젝트의 본 결과를 보여 줄 때 |
| `random` | 무작위 행동 | 비교용. 곧 멸종합니다 |

- `--seed 숫자`는 초기 배치를 정합니다(기본 42). 같은 숫자면 같은 지도에서 시작합니다.
- `trained`는 `data/q_tables/` 폴더의 Q-Table 파일 4개가 있어야 합니다. 없으면 안내 문구가 나오며, 먼저 `--train`을 실행해야 합니다.

**뷰어 조작**

| 키 / 버튼 | 동작 |
|---|---|
| `Space` | 재생 / 정지 |
| `→` | 한 step만 진행 |
| `R` | 새 배치로 다시 시작 |
| `G` | 개체수 그래프 창 열기 (step 0부터 전체 기간) |
| 속도 버튼 | step/초 선택. "최대"는 가능한 한 빠르게 |
| 격자 클릭 | 그 칸의 동물이나 지형 정보 보기 |

**화면 읽는 법**

- 초록색은 풀(토끼 먹이), 점무늬 올리브색은 관목(사슴 먹이), 파란색은 물, 보라색은 토끼 굴입니다.
- 빨간 테두리가 있는 동물은 배고픔이나 목마름이 위험한 상태입니다.
- 포식자를 클릭하면 시야(노란 영역)와 사냥 반경(빨간 점선)이 표시됩니다.
- 오른쪽 그래프는 초식동물 합계(왼쪽 눈금)와 육식동물 합계(오른쪽 눈금)입니다.

진동 한 주기가 약 2,800 step이므로, 출렁임을 보려면 속도를 "최대"로 두고 수천 step을 돌려야 합니다.

### 4-2. 학습 `--train`

4종의 Q-Table을 처음부터 다시 학습합니다.

```powershell
python -m food_chain --train
```

- 기본은 200 episode × 400 step이고 약 6분 걸립니다.
- 결과는 `data/q_tables/`의 `rabbit.json`, `deer.json`, `fox.json`, `wolf.json`과 `data/results/train_log.csv`에 저장됩니다. **기존 파일을 덮어씁니다.**
- `food_chain/config.py`의 수치를 바꿨다면 다시 학습해야 그 변화가 학습된 정책에 반영됩니다. 규칙 기반 정책은 학습이 필요 없습니다.
- `--episodes 숫자`로 episode 수를 바꿀 수 있습니다.

### 4-3. 평가 `--eval`

무작위 / 규칙 기반 / 학습된 정책을 같은 조건에서 돌려 비교합니다.

```powershell
python -m food_chain --eval
```

- 기본은 seed 6개 × 4,000 step입니다. `--seeds`, `--steps`로 바꿉니다.
- 화면에 정책별 공존 여부, 종별 개체수, 사망 원인이 표로 나옵니다.
- `--eval-ablation`을 붙이면 "포식자가 없을 때" 대조 실행이 추가됩니다. 포식자가 실제로 영향을 주는지 볼 때 씁니다.
- `--no-immigration`을 붙이면 외부 유입 없이 평가합니다. 외부 유입은 포식자가 0마리가 됐을 때 바깥에서 소수가 들어오는 규칙이고, 기본은 켜져 있습니다.

```powershell
python -m food_chain --eval --no-immigration --results-dir data/results/noimm
```

`--results-dir`을 주지 않으면 유입을 켠 결과 파일을 덮어쓰므로, 유입을 끌 때는 위처럼 다른 폴더를 지정하세요.

### 4-4. LV 유사성 측정 `--lv`

포식자–피식자 개체수가 로트카-볼테라 모델처럼 진동하는지 숫자로 잽니다.

```powershell
python -m food_chain --lv --policy rule --seeds 6 --steps 16000
```

- 기본은 seed 4개 × 8,000 step이고 외부 유입은 끕니다. 발표에 쓴 결과는 위 명령(seed 6개 × 16,000 step)으로 만든 것입니다.
- 여우–토끼, 늑대–사슴 쌍마다 다음을 출력합니다.

| 항목 | 뜻 |
|---|---|
| 주기 | 개체수가 한 번 오르내리는 데 걸리는 step |
| 지연 / 주기 | 포식자가 피식자를 얼마나 늦게 따라가는가. LV 이론값은 약 0.25 |
| 교차상관 | 두 종의 오르내림이 얼마나 맞물리는가 (1에 가까울수록 강함) |
| 진폭 | 최대 개체수 ÷ 최소 개체수 |
| 포식 사망 비율 | 피식자가 줄어드는 구간에서 잡아먹혀 죽은 비율 |

- 반복이 2번 미만이면 "측정 불가"로 나옵니다.
- `--policy trained`로 학습된 정책도 잴 수 있습니다.

### 4-5. 차트 `--plots`

`data/results/`의 CSV를 읽어 PNG 차트를 `data/results/plots/`에 만듭니다.

```powershell
uv run python -m food_chain --plots
```

- 시뮬레이션을 돌리는 명령이 아닙니다. 이미 있는 CSV로 그림만 그립니다. 새 결과로 그리려면 먼저 `--eval`이나 `--lv`를 실행하세요.
- `uv run`이 오류를 내면 `uv run --no-sync python -m food_chain --plots`를 써 보세요(이 프로젝트를 만든 PC에서는 이 형태가 필요했습니다).
- 이미 만들어진 그림을 보기만 할 때는 명령이 필요 없습니다. 폴더를 열면 됩니다.

```powershell
ii data\results\plots
```

| 파일 | 내용 |
|---|---|
| `lv_timeseries_rule.png`, `lv_timeseries_trained.png` | 16,000 step 개체수 시계열 (발표 핵심 그림) |
| `lv_seeds_*.png` | 6개 seed를 한 장에 |
| `lv_phase_*.png` | 피식자 수 대 포식자 수 궤적 |

## 6. CSV 파일의 역할

`data/results/`의 CSV는 **평가와 측정을 돌린 결과를 저장해 둔 기록**입니다. 시뮬레이션이나 뷰어가 실행될 때 읽는 파일이 아니라서, 없어도 뷰어·학습·평가는 그대로 동작합니다. 쓰이는 곳은 두 군데입니다. 차트를 그릴 때 읽고, 발표 자료의 수치를 여기서 확인합니다.

| 파일 | 내용 | 만드는 명령 | 크기 |
|---|---|---|---|
| `eval_summary.csv` | 정책·seed별 요약(공존 여부, 평균 개체수, 사망 원인) | `--eval` | 작음 |
| `eval_random.csv`, `eval_rule.csv`, `eval_trained.csv` | 매 step의 종별 개체수·사망 등 원본 기록 | `--eval` | 각 약 3.5MB |
| `eval_rule_nopred.csv`, `eval_trained_nopred.csv` | 포식자 없음 대조의 매 step 기록 | `--eval --eval-ablation` | 각 약 3.2MB |
| `eval_ablation.csv`, `eval_benchmark.csv`, `eval_crossplay.csv` | 대조 실험, 고정 개체수 비교, 정책 교차 조합의 요약 | `--eval` | 작음 |
| `lv_summary.csv` | 쌍·seed별 주기, 지연, 교차상관, 진폭 | `--lv` | 작음 |
| `lv_rule.csv`, `lv_trained.csv` | 16,000 step의 매 step 개체수 기록 | `--lv` | 각 약 3.3MB |
| `train_log.csv` | episode별 보상, 수명, 사냥 횟수, Q-Table 크기 | `--train` | 작음 |
| `noimm/` 폴더 | 외부 유입을 끈 평가 결과(같은 구성) | `--eval --no-immigration` | 약 11MB |

- **요약 파일(작은 것)** 은 발표 표의 수치가 들어 있어 보관할 가치가 있습니다.
- **매 step 원본 기록(큰 것)** 은 차트를 다시 그릴 때만 필요합니다. 지워도 위의 명령으로 다시 만들 수 있습니다. 다만 평가는 seed가 고정되어 있어 같은 결과가 나오지만, 코드나 수치를 바꾼 뒤라면 결과도 달라집니다.
- CSV를 다시 만들면 기존 파일을 덮어씁니다. 발표에 쓴 수치를 남겨 두려면 실행 전에 복사해 두세요.

## 7. 자주 겪는 문제

- **`No module named food_chain`:** 프로젝트 폴더가 아닌 곳에서 실행했습니다. 터미널의 현재 위치를 확인하세요.
- **`trained` 정책에서 Q-Table을 찾지 못한다는 안내:** `data/q_tables/`에 파일이 없습니다. `python -m food_chain --train`을 먼저 실행하세요.
- **Q-Table을 불러올 수 없다는 오류:** `config.py`에서 State 구성을 바꾼 뒤 예전 Q-Table을 쓰려 한 경우입니다. 다시 학습하세요.
- **`--plots`에서 matplotlib이 없다는 오류:** `python` 대신 `uv run python`으로 실행하세요.
- **뷰어가 느리다:** 속도를 "최대"로 두면 화면 갱신보다 계산이 앞서갑니다. 그래프 창(G)을 닫으면 조금 빨라집니다.
- **진동이 안 보인다:** 한 주기가 약 2,800 step입니다. 규칙 기반 정책으로 5,000 step 이상 돌려 보세요.
